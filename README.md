This repository holds one semester of work on one question: **is this product worth doing?**

By December it will contain a demand curve estimated from data you collected, a profit model
built on costs you researched, a competitive analysis against a real rival, and a recommendation
you can defend. Right now it contains empty folders. That is the point — you are going to fill
them in order, and at the end the folders *are* the argument.

## Where things go

| Folder | What goes in it | Weeks |

| `project/` | The archived product page, why you chose it, your model map | 2–3 |

Put files where they belong when you make them. A repository organised at the end is a
repository reorganised badly.

## Committing

You do not need to know git. Everything here can be done in the browser: open a folder, click
**Add file**, upload or create, write a one-line message, commit.

**If you would rather work on your own machine**, use
[GitHub Desktop](https://desktop.github.com) rather than the command line. It signs in through
your browser, so there is no token to create — clone the repository, work in the folder, then
commit and push from the app. Fetch before you start if you have also been editing on the
website.

**Commit as you go, not at the end.** Not because commit counts are graded — they are not — but
because a repository that accumulates is one you can look back through when a number stops making
sense in November, and a repository that appears in one lump on the last night is not.

A repository with no commits cannot be graded.

## The AI log

Every milestone includes a log of the prompts you used and the responses you acted on. It is
graded on **supervision**, not on whether you used AI — you are expected to.

Good supervision looks like: checking a tool against a known answer before trusting it; noticing
a result that looks wrong and finding out why; rejecting an answer and saying what was wrong with
it. Include the dead ends. A log with no wrong turns in it is either a lie or a sign you were not
looking.

## Keep private

Set your copy to **Private** when you create it, and keep it that way. It will contain survey
responses from real people. Do not make it public, and do not commit anyone's name, email address, or anything else
that could identify them — strip those columns before you commit any dataset.
